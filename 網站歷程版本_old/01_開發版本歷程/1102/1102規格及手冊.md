## 1. 專案開發原則與兩階段藍圖

### 1.1 五大核心開發原則
1. **先做對購物流程**：不急著做複雜功能，優先確保顧客下單與對帳體驗順暢。
2. **雙軌銷售角色明確**：每日現流海鮮是首頁主角，常態冷凍商品為穩定的補充銷售。
3. **現流商品防超賣能力**：正式版必須具備真正的即時庫存同步與原子性扣除（Transaction）能力。
4. **資料長期保存**：訂單、付款、運費及公開/私人留言紀錄必須能長期保存，不能自動過期刪除。
5. **測試與正式營運分離**：第一階段內部測試資料不直接作為正式營運資料。

### 1.2 兩階段開發計畫

* **第一階段：內部測試（目前完成目標）**
  * 優先讓小商人與內部人員實際操作網站、驗證購物流程。
  * 確認首頁雙欄排列、選購流程、模擬庫存跳動、匯款回報對帳、運費合併計算與本地端對話留存。
* **第二階段：正式實裝上線（後續雲端建置）**
  * 建立正式 Firebase 專案，接入 Google 會員登入 (UID 辨識)。
  * 建置 Firestore 資料庫、實時監聽 (onSnapshot) 與防超賣原子交易機制。
  * 部署靜態網站至 Firebase Hosting。

## 2. 網站首頁版型與介面規格 (左 2/3、右 1/3)

首頁採用簡潔、直接的購物導向，不需冗長文字描述，分為四大主要區塊：

| 區域/區塊 | 內容與功能 | 顯示與互動方式 |
| :--- | :--- | :--- |
| **左側 2/3 (上)** | **每日現流搶購區** | 每日約 1～2 項限量現流，含照片/短影音、價格、剩餘數量、下拉選擇器與搶購按鈕。 |
| **右側 1/3** | **冷凍常規專區** | 從上到下連續直落排列顯示全部冷凍商品，固定品項與價格，不需進入第二層頁面即可加購。 |
| **左側 2/3 (中)** | **影音展示區** | 放在商品區下方，展示崁仔頂現場叫賣、漁獲介紹等短影音，作為輔助不搶走購買區重點。 |
| **左側 2/3 (下)** | **常見問答 Q&A** | 涵蓋下單、付款、匯款回報、出貨時間、運費計算，並頂部嵌入 **9:16 新人須知海報預覽**。 |

## 3. 商品與訂單規格 (現流搶購 vs 冷凍常規)

### 3.1 每日現流商品
* **數量與特性**：每日約 1～2 項，深夜親自走訪魚市挑選，去鱗去鰓清內臟真空處理（淨重定價）。
* **庫存即時動態**：剩餘數量即時跳動，當庫存扣減時，數字會產生 **1.8 倍彈跳放大與紅橙光暈** 動畫；數量低於 3 份時觸發全幅警示條。
* **超賣防護**：測試版採用前端模擬扣減，正式版連動 Firestore Transaction 真實資料庫。

### 3.2 冷凍常態商品
* 提供深海大白鯧、包餡火鍋料與基隆在地特色海產。
* 管理員可在後台隨時調整商品資訊、價格、成本與進行商品上下架。

### 3.3 訂單流程 SOP
1. **買家選購** ➔ 選擇現流或冷凍品項與數量加購物車。
2. **送出訂單** ➔ 系統記錄 UID（或測試帳號）、商品明細、數量、金額與時間。
3. **買家轉帳** ➔ 依照總金額完成轉帳，於當日 23:59 前回報末 5 碼與收件門市。
4. **管理員核對** ➔ 人工確認銀行入帳，更新訂單付款狀態。
5. **合併出貨** ➔ 同一買家在同一出貨週期內的訂單，系統自動合併計算運費。

## 4. 運費與出貨週期規則 (自動併單計算)

### 4.1 出貨週期
* **每週二 12:00 開始** 至 **每週日 12:00 截止** 為一個出貨週期。
* 暫停寄庫機制，當週訂單一律當週結單、於 **「隔週二至週三」** 依序寄出包裹。

### 4.2 運費自動合併計算規則
系統根據同一買家 (UID) 在同一出貨週期內已核對的訂單累計金額自動計算運費：

| 同週累計消費金額 | 運費優惠 |
| :--- | :--- |
| **滿 NT$ 3,000** | **免運費** |
| **NT$ 2,000 ～ NT$ 2,999** | **超商店到店 $60** |
| **未滿 NT$ 2,000** | **超商店到店 $130** |

* *範例*：同一買家週二下單 \$1,200，週五再下單 \$1,000，累計 \$2,200，系統自動判定運費為 \$60。

## 5. 會員識別與留言紀錄保存規範

1. **會員識別 (UID)**：
   * 正式版採用 Google 登入，以 UID 作為買家訂單合併、對帳及留言紀錄的核心識別。
2. **雙軌留言板永久留存**：
   * **公開留言板**：買家可互相交流、查看討論與管理員回覆。
   * **私人留言板**：買家與管理員進行個別改單、變更門市或私密對帳。
   * **保存原則**：不設定自動到期刪除，登出或關閉網站後重登仍可調閱，僅管理者明確執行刪除時才移除。

## 6. 前台顧客體驗與手機端/LINE 導流優化

1. **防 LINE 快取設定**：
   * 網頁設有 `Cache-Control: no-cache` 標籤，確保手機從 LINE 點進來都是最新鮮魚貨狀況。
2. **大拇指黃金操作區 (Thumb Zone)**：
   * 手機畫面右下角常駐 **`💬 留言對話 (公開/私訊)`** 懸浮按鈕。
   * 新人指南彈窗設計為 9:16 高畫質圖片，且底部按鈕方便大拇指順手點擊。
3. **防重複下單**：
   * 搶購按鈕點擊後自動顯示「處理中...」並鎖定，防止網路卡頓時重複扣減庫存。

## 7. 管理者後台控制台 (Admin Console) 完整操作 SOP

### 7.1 後台進入方式
* 沙盒列切換為「管理者 (`twvisa2009@gmail.com`)」➔ 頂部導覽列點擊 **「⚙️ 後台管理」**。

### 7.2 五大管理頁籤說明
* **訂單與對帳核銷**：審核買家下單明細、末 5 碼與核銷狀態。
* **改單與留言總紀錄**：查看公開與私人對話，並提供 **「匯出留言對話檔 (.json)」** 備份功能。
* **現流商品上架與庫存**：新增每日現流品項、設定圖片/短影音網址，並可一鍵 **「下架商品」**。
* **常態冷凍商品管理**：維護冷凍品項、價格與成本，支援一鍵下架。
* **財務損益與統計報表**：計算營業額、進貨成本、毛利與毛利率，並支援 **「匯出 UTF-8 BOM CSV 報表」**（Excel 開啟不卡亂碼）。

## 8. 技術架構與第二階段 Firebase 雲端部署指南

### 8.1 預定技術堆疊

| 項目 | 採用技術 | 用途 |
| :--- | :--- | :--- |
| 前端網頁 | HTML5, Tailwind CSS, JavaScript | 商品展示與購物操作 |
| 版本控制 | GitHub | 程式碼保存與版本控管 |
| 會員認證 | Firebase Authentication | Google 登入與 UID 綁定 |
| 雲端資料庫 | Firebase Firestore | 商品、訂單、庫存與雙軌留言保存 |
| 即時同步 | Firestore `onSnapshot` | 多人同時在線庫存與留言跳動 |
| 防超賣機制 | Firestore Transaction | 原子性扣除庫存 |
| 網站託管 | Firebase Hosting | 免費 HTTPS 靜態網頁託管 |

### 8.2 上線部署步驟 (CLI)
1. 安裝 Node.js 與 Firebase CLI（`npm install -g firebase-tools`）。
2. 在 Terminal 執行 `firebase login` 並選擇 Google 帳號。
3. 執行 `firebase init hosting` 並選擇建好的專案。
4. 執行 `firebase deploy` 完成上線！
